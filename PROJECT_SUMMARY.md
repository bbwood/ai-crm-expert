# AI CRM Expert - Project Summary

## What Was Built

A complete MVP of an automotive retention expert system using a multi-layer prompt architecture. The system transforms PDF service invoices into personalized, trust-building customer engagement messages.

## Core Components

### 1. Multi-Layer Prompt System

Each AI message is generated by composing 4 layers:

**System Layer** (`prompts/system/`)
- Defines the AI's personality as a trusted automotive advisor
- Establishes core values: transparency, safety-first, no pressure
- Sets communication style: friendly, clear, action-oriented

**Context Layer** (Generated at Runtime)
- Customer profile (name, contact, visit history)
- Vehicle details (year/make/model, mileage, VIN)
- Service history (recent work, recommendations, findings)
- Shop information

**Task Layer** (`prompts/task/`)
- Specific instructions for each communication type
- 5 task types covering the customer lifecycle
- Tone guidelines and example outputs

**Meta Layer** (`prompts/meta/`)
- Self-review and quality control
- Scores messages on clarity, trust, and retention impact
- Auto-revises if any score falls below 8/10

### 2. PDF Processing Pipeline

**Input:** Service invoice PDF
**Output:** Structured context JSON

Pipeline stages:
1. **Upload** → Store PDF file
2. **Parse** → Extract text using pdf-parse
3. **Extract** → Pattern matching for customer/vehicle/service data
4. **Normalize** → Convert to standard schema
5. **Generate Context** → Build JSON context object

### 3. Task Selection Logic

Automatically selects the best task type based on business rules:

```typescript
if (hasDeclinedWork() && 30-90 days) → followup_declined_work
else if (isMaintenanceOverdue()) → overdue_maintenance_reminder
else if (daysSinceLastVisit > 365) → inactive_customer_reconnect
else if (daysSinceLastVisit <= 7) → post_service_checkin
else if (daysSinceLastVisit 8-30) → review_request
```

### 4. AI Service

- Uses Anthropic's Claude API
- Composes prompts from all 4 layers
- Parses response to extract message + self-review scores
- Supports variant generation for A/B testing

### 5. Logging & Analytics

- File-based JSONL logging (easily upgradeable to database)
- Tracks: context, task type, message, scores, outcomes
- Provides statistics: runs by task, average scores, outcomes
- Enables continuous learning and prompt improvement

## API Endpoints

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/health` | GET | Health check |
| `/api/upload-invoice` | POST | Upload & parse PDF only |
| `/api/generate-message` | POST | Generate message from context |
| `/api/process-invoice` | POST | **Full pipeline** (upload → message) |
| `/api/log-outcome` | POST | Record message outcome |
| `/api/customer-history/:id` | GET | Get customer's run history |
| `/api/stats` | GET | Performance statistics |

## Philosophy & Design Principles

1. **Customers should feel advised, not sold**
   - No pressure tactics
   - Transparent reasoning
   - Respect for autonomy

2. **Earn the next visit through trust**
   - Focus on safety and value
   - Personal, not templated
   - Explain the "why"

3. **Modular and maintainable**
   - Each layer is independent
   - Easy to test and update
   - Clear separation of concerns

4. **Data-driven improvement**
   - Log every interaction
   - Track outcomes
   - Measure quality scores

## Contributing

To add a new task type:

1. Create prompt file in `prompts/task/`
2. Add task type to `types.ts`
3. Update task selector logic in `taskSelector.ts`
4. Add file mapping in `promptComposer.ts`

To customize for your shop:

1. Edit system prompt for your shop's voice
2. Update shop info in API requests or context generator
3. Customize task prompts for your services
4. Adjust task selection rules for your business
